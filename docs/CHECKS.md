# 自检与守卫

`scripts/check_site.py` 只盯一件事：**构建成功但站点已经坏掉**的问题。
这类错不会自己浮出来——构建是绿的、HTTP 是 200、页面能打开，只是某块地方不对。

## 为什么需要它

内容源有两层：自动同步的快照（`data/registry.json`）与手写叠加层（`data/projects.py`）。
最典型的翻车方式是：

- 改了 repo 名或 APK 文件名 → 站点点进去 404，构建一片绿
- 往 CSS 里插一段没闭合的 `@media` → 之后的规则全部失效，页面变成无样式纯文本
- 把卡片做成整块 `<a>`，里面又有标签链接 → 浏览器把内层链接提到外层之外，卡片被拆碎
- 同步快照里明明有新版本，页面上却渲染了旧版本 → 商店页显示旧版本
- 新增的仓库没生成页面 → 用户搜得到、点不到（「新项目上不了站」又回来了）
- 数据渲染了一半：`update.json` 有了、详情页的校验值没有 → 功能看着在，其实没有

这些的错误面都在**运行时**，所以检查必须真的做运行时会做的事：
发 HTTP 请求、数产物、比对 DOM 结构。

## 七类守卫，以及每条真的会怎么红

每条都做过**变异测试**：注入对应缺陷，确认它会红。第一版里有三条是橡皮图章，
写下来是因为「守卫本身失效」比「没有守卫」更危险——它会让人以为已经守住了。

### 一、产物完整性
`sitemap.xml`、`robots.txt`、`feed.xml`、`icon.svg`、`tags.html`、`404.html` 等等。
少一个文件在浏览器里就是 404，而构建本身是绿的。

### 二、样式表能被完整解析
去掉注释与字符串后数大括号，必须配平。

> **真发生过**：插了一段 `@media (prefers-reduced-motion)` 却没闭合，结果它之后
> 的所有规则失效，页面变成没有样式的纯文本。浏览器不报错、文件 HTTP 200、
> 前 6 条规则照样能解析出来——肉眼只在「打开页面」时才发现。

### 三、页面骨架一致性
- 导航项数在所有页面一致（加页面时漏一处，页面上看不出来）
- 主题脚本排在 `<link rel=stylesheet>` 之前（否则深色用户先闪一帧浅色）
- 可索引页面必须有 `canonical`；所有页面必须有 `icon`
- 站内锚点必须存在（标签、技术栈都是页内锚点，拼错就是「点了没反应」）

> 这条守卫的第一版是橡皮图章：它找 `data-theme` 出现在样式表之前——而
> `<html data-theme>` 就在第 2 行，永远在前。现在改成定位内联脚本里那段
> `localStorage.getItem(K)`。

### 四、标签索引双向一致
- 清单里的每个标签都出现在 `tags.html`（少一个 → 首页那颗 pill 是死链）
- `tags.html` 里不许出现清单外的标签（多一个 → 引用了不存在的标签）

### 五、卡片结构：不允许 `<a>` 嵌套 `<a>`
断言首页卡片是 `<div class="card reveal">`，且里面恰好一个 `.cardhit`。

> **真发生过**：整张卡片是 `<a>`，里面又有指向标签页的链接。浏览器不会报错，
> 它当场把内层 `<a>` 提到外层之外——卡片被拆成两半，页面上多出几个
> 「只有技术栈、没有标题」的幽灵方块。而 HTML 源码、构建日志、状态码全正常。

### 六、Release 事实投影
- 商店页每个 APK 的体积、链接、版本号必须与 `releases.json` 一致
- 项目详情页必须显示当前版本（用户从搜索直接落到详情页，看不到就得再跑一趟商店）
- `feed.xml` 条目数必须等于可安装应用数

### 七、下载源配置
- 地区名单必须覆盖 CN/HK/MO/TW 的主要 IANA 时区
- 官方直连必须存在且 `role=fallback`
- 每个加速前缀必须是 `https://` 且以 `/` 结尾（拼接方式是 `prefix + URL`）

> 地区名单那条的第一版也是橡皮图章：它在**文件文本**里找 `Asia/Guangzhou`，
> 而文件注释里正解释着「为什么补它」，文本里一直有。现在从 `exec()` 出来的
> 变量里取。

## 商店页下载层的守卫

下载逻辑坏了在页面上看不出来（按钮在、样式对，只是慢或者下不来），所以必须由检查盯着：

| 断言 | 防止什么 |
|---|---|
| `MAX_PARALLEL` 被赋值且 ≥ 2，且真的出现在发起循环里 | 退化成串行，8 个包排队等建连 |
| 剥掉注释后**不许出现 `fetch(`** | 有人「好心」把已证伪的测速方案加回来 |
| `slowDirect()` 必须被 `return` / 三元 / 赋值调用 | 定义了却不参与决策 = 地区判断没生效 |
| 不许出现 `effectiveType` | 它会被随机报成 3g 导致误开加速，语义也不对 |
| `sourceFor` 里必须有 `i % list.length` | 退化成「所有包押在同一个源」 |
| `candidates()` 必须 `a.concat([d])` | 官方直连不再垫底，失去兜底 |
| 状态条 `#srcbar` / `#srctoggle` 必须存在 | 默认开加速就必须让用户看得见、改得动 |
| 文案里「每批 N 个」必须等于代码里的 `MAX_PARALLEL` | 改了常量忘改文案 |
| 提到「多线程下载」必须同时出现「实测不成立」 | 把已否掉的做法当卖点讲 |

### 那条 JS 语法检查的由来

本版在浏览器里点开搜索框敲了三个字，才发现**输入框能打字、但永远没有结果**。

根因是搜索脚本里一个字符类正则：`/[.*+?^${}()|[\]\\]/g`。
`SEARCH_JS` 当时是普通三引号字符串，Python 先把 `\\` 折成 `\`，
于是 JS 收到 `/[.*+?^${}()|[\]\]/g` —— 字符类被提前闭合，**整段脚本解析失败**。

那个状态下：构建全绿、自检全绿（当时还没有这条断言）、HTTP 200、
页面外观完全正常、输入框能获得焦点、能打字。只有真敲字才看得见。

这就是「静默失效」的教科书形状。所以现在有一条只能靠**执行**来验的断言：
把每张页面里的内联 `<script>` 抽出来交给 `node --check`。
CI 的 runner 自带 node；本机没有 node 时它会**明确说跳过**，而不是静默通过。

### 另外两条只能"跑"才发现的

- **表头排序点不动**：脚本被塞在 `<head>` 里，`querySelectorAll` 执行时 DOM 还不存在。
  静态检查只查了 `data-sort` 属性在不在，所以全绿。
- **对比表在 390px 上横向溢出**：`table-layout:auto` 按内容分配宽度，
  一列长日期就能把项目名挤出屏幕。改成 `fixed` + 列宽算死，溢出与否变成可算的。
