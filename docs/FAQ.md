## 站点侧

**Q1. 这个站点为什么不用 MkDocs / VitePress / Next？**

因为它们会给一个「主张零依赖」的账号加上一套会过期的构建链。

站点的全部需求就是「把结构化数据渲染成 HTML，再放一份搜索索引」——
Python 标准库足够，产物是纯静态的：克隆下来双击 `index.html` 就能看，换任何托管都不用改代码。

代价是没有插件生态。搜索、图标、死链检查、下载加速、主题切换、标签索引、
PWA 三件套全是手写的，因为它们都不需要依赖。这笔账划算与否，取决于你更怕哪一种：
「依赖哪天升不上去」还是「功能少几个」。

**Q2. 站点上的版本号是从哪来的？我需要在哪改？**

**哪都不用改。** 版本号来自 `data/registry.json`，那是 `scripts/sync.py` 从 GitHub API 同步的。
商店页、详情页、`update.json`、`stats.json`、对比表、时间线，全部读同一份。

这条是这个站点最重要的一条纪律。它曾经被违反过两次，两次都翻车：
页面写着 v2.6.0，线上 Release 已经是 v2.7.1——因为版本号是手抄在 markdown 里的。

**Q3. 我发了一个新仓库，站点上什么时候能看到？**

下一次 `sync` 之后，最多一小时。想更快的话，在**那个新仓库**配一个 webhook →
`https://api.github.com/repos/ice-wocker/icesuite/dispatches`，body `{"event_type":"release"}`。

新仓库第一天的文案取仓库描述，标一个「自动收录」。想写得好看，就在
`data/projects.py` 里加一条同 `repo` 的条目，只写你想覆盖的字段。

**Q4. 「自动收录」的项目为什么亮点是空的？**

不是空的，是**换了一种亮点**。没有人工写 `highlights` 的项目，详情页会把
「关于这个项目」渲染成 GitHub 上可核实的事实：主要语言、Star/Fork、最近提交、发版次数、
包名与 sha256。这些每一条都能点开仓库核实，而「一款优秀的应用」这种话做不到。

**Q5. `sha256` 为什么会是 `null`？**

因为 GitHub 的资产元数据里没有它。本站不推算——从版本号猜一串十六进制是能做出来的，
但那串东西一旦被下载方当真，比没有更糟。

`update.json` 顶层有一个 `verify` 字段，就是告诉你「这份清单里有多少条能验」：

```json
"verify": { "sha256_covered": 12, "size_covered": 12 }
```

12/12 是健康。10/12 意味着有两个包的校验值拿不到，客户端可以据此提示用户。

**Q6. 商店页的「一键下载」为什么不设成「多线程下载」？**

实测过：同一个 58.3 MB 的包，同一网络下开 1 条 / 4 条连接总吞吐都是 ~6.2 MB/s。
单连接吞吐是固定的，加连接不增带宽。

但**并行发起多个包**是真实收益——小包慢在建连（TTFB 0.3~1.3 秒），不在带宽。
所以每批并行 5 个，总速度是几条连接之和。

**Q7. 为什么不自动测速选源？**

做过，是假的。GitHub Release 会 302 到 `release-assets.githubusercontent.com`，
那一跳不带 `Access-Control-Allow-Origin`，三个反代同样不带。浏览器读不到响应字节数，
任何基于 `fetch` 的计时恒为 0。

更糟的是它**看起来能用**：探针全失败后悄悄退回官方直连，页面照常下完文件。
区别只是白花了 4 次请求，而那个「智能选源」从来没生效过。

现在的做法是按**地区**判断（时区 + 语言，零请求），因为「直连在大陆慢」这个差异是稳定的。

**Q8. 站点能装到桌面吗？装了之后能离线用吗？**

能装，能离线翻，**但离线不能下 APK**。

- 能离线：首页、商店、时间线、对比、集合、数据、搜索、版本号、sha256
- 不能离线：下载 APK（跨域资源，CORS 不允许 Service Worker 读响应体）

页面上明确写了这一点，不制造假确定感。细节见 [PWA](PWA.md)。

**Q9. 为什么要用「先网络后缓存」，缓存优先不是更快吗？**

更快，但会坏。缓存优先意味着用户装完之后一直看到旧页面，而且**无法自愈**——
这是最糟的一种 PWA 故障：它看起来正常工作，只是内容永远停在某一刻。

「装上去之后再也不会更新」比「不能离线」严重得多。

**Q10. `content.json` 是干什么的？**

产物自索引：每个文件的 sha256、字节数，以及一个由全部内容决定的 `build.id`。

它是「同一 commit 同一产物」这句话唯一的证据。你可以下载整站，用那个 JSON 逐个文件核对。
它**刻意没有 `generated_at`**——带上时间就不再可复现，那条承诺当场作废。

**Q11. 为什么要有两个变异测试脚本？**

`mutate_test.py`（15 条）验的是老页面和老产物，`mutate_v2.py`（29 条）验这一版新增的。
分开跑的好处是 CI 日志里能一眼看出**红的是老守卫还是新守卫**。

它们的判定方式是：注入缺陷 → 跑 `check_site` → 要求非零 → **且要求红在预期的原因上**。
只变红不核对不算，因为它可能是被别的东西撞红的。

**Q12. 怎么证明这些守卫本身没有失效？**

三层：

1. 每条守卫都有一条对应的变异用例（注入 → 必须红 → 且红对地方）
2. `mutate_v2.py` 的 `edit_page()` 会同步刷新 `content.json` 哈希——
   否则改页面的用例会被完整性断言先抓走，新守卫等于从没被验过
3. CI 的 `guards` job 末尾有一条**反向自检**：手动改坏一个产物，确认 `check_site` 真的会红

第三层是必须的。如果 `check_site` 哪天变成永远返回 0，两份变异测试会一起变绿——
双重失效，而且表面上全绿。

**Q13. 站点会不会哪天突然要求我「记得改什么东西」？**

不会，这是这个站点唯一的立场：**凡是要求人记得的，都是迟早会忘的。**

新仓库自动上站、版本号自动同步、sha256 自动取、更新记录自动抓 Release 正文、
集合按规则自动重算、体检按事实自动分级。人只写「这个项目该怎么被描述」——
那是机器替代不了的部分。

**Q14. 为什么不做评论区 / 评分 / 访问统计？**

要后端、要防滥用、要处理 GDPR，和「零依赖、无追踪、无 Cookie」直接冲突。
为了一个评论框破掉整站的立身之本，不值。

同理，`graph.json` 里没有「用户也看了」这类共现边——这个站点没有埋点，
也就不该有一张假装懂行为的图。

## 一、选模型

**Q1. 我应该下多大的模型？**

按可用内存选，不要按「参数量越大越聪明」选。手机上的瓶颈是内存与带宽，不是算力。

| 机型内存 | 建议参数量 | 建议量化 | 上下文 | 预期速度 |
|---|---|---|---|---|
| 4 GB | 0.5B | Q4_0 / Q4_K_M | 2048~4096 | 10~20 tok/s |
| 6 GB | 0.5B~1.5B | Q4_K_M | 4096~8192 | 12~25 tok/s |
| 8 GB | 1.5B~3B | Q4_K_M | 8192 | 10~20 tok/s |
| 12 GB+ | 3B~4B | Q4_K_M | 8192~16384 | 8~15 tok/s |
| 16 GB+ | 7B（勉强） | Q4_0 | 4096 | 2~5 tok/s |

超过 7B 在手机上不具可用性：能加载，但每秒钟吐两三个字，体验接近不可用。

**Q2. Q4_K_M、Q4_0、Q8_0 怎么选？**

| 量化 | 体积 | 质量 | 建议 |
|---|---|---|---|
| `Q4_0` | 最小 | 一般 | 内存极紧张时用 |
| `Q4_K_M` | 小 | 好 | **首选**，质量与体积平衡点 |
| `Q5_K_M` | 中 | 更好 | 内存宽裕时用 |
| `Q8_0` | 大 | 接近原始 | 手机上基本没必要 |

`K_M` 是「K-quant，中等混合精度」，对敏感层用更高位宽。同样的 bit 数下质量优于旧格式。

**Q3. instruct 和 base 有什么区别？**

`instruct`（或 `chat`）版本经过指令跟随微调，能听懂「帮我总结一下」这类话。
`base` 版本只会续写文本，你问它问题，它会接着写更多问题。

**智能体功能强烈依赖 instruct 版本**——base 模型不会按格式输出工具调用，整条闭环走不通。

**Q4. 为什么有的模型「不肯动手」？**

三层原因，按可能性排：

1. **模型太小**（<1B）：指令跟随能力有限，容易只顾着回答，忘了调工具。换 1.5B~3B 明显更好。
2. **不在它的训练分布里**：有些模型见过 function call 格式，有些没见过。Qwen 系列、MiniCPM 系列对工具调用友好。
3. **提示词太长**：超过 2.5B 的模型会自动收到压缩版提示词；如果你手动改过系统提示词，试试恢复默认。

排查步骤：先在输入框敲 `/run ls`，确认终端通道本身是通的；再换一个 instruct 模型对比。

**Q5. 同一个模型有几十个 GGUF 文件，下哪个？**

看文件名里的量化标记。一个仓库通常同时提供 `Q2_K`、`Q3_K_M`、`Q4_K_M`、`Q5_K_M`、`Q8_0`、`FP16`。

选 `Q4_K_M`。如果只有 `Q4_0` 和 `Q8_0`，选 `Q4_0`。

另外注意 `mmproj` 开头的文件是视觉投影层（多模态用），单独下载但本项目不支持多模态输入，可以跳过。

## 二、速度

**Q6. 为什么我的速度只有 3 tok/s？**

按这个顺序排查：

| 检查项 | 怎么确认 |
|---|---|
| 模型太大 | 3B 以上在 8 GB 机型上本就慢 |
| 机型太老 | 缺 dotprod 的 arm64 只能跑基线档，慢约 40% |
| 上下文开太大 | 32768 的预填充要几十秒 |
| 后台应用 | 关掉后台再测 |
| 散热降频 | 连续生成 10 分钟以上会明显变慢 |
| 电池模式 | 省电模式会限制 CPU 频率 |

**Q7. 首字很慢但后面很快，正常吗？**

正常。首字延迟 = 预填充时间，要把整个 prompt（系统提示 + 历史 + 本轮输入）过一遍模型。
后面每个 token 只需一次前向，所以快得多。

前缀复用能显著降低多轮对话的预填充：三轮累计从 655 降到 328 tokens。

**Q8. 为什么开了智能体之后变慢了？**

因为每一轮工具调用都要重新生成一次。8 步上限意味着最坏情况要生成 8 次。

优化方式：把复杂任务拆成几条消息，或者关掉智能体用斜杠命令手动执行。

**Q9. 状态条第 90 百分位是什么？**

P90 是最近 12 轮里第 90 百分位的速度，用它比用平均值更能反映「正常情况下能有多快」——
一次切后台的异常会把平均值拉低，但拉不动 P90。

如果 P90 也明显低于以前，说明是设备状态变了（散热、后台），不是偶发。

## 三、内存与存储

**Q10. 为什么默认上下文是 8192，我能开更大吗？**

能，上限 32768。但看这个表：

| 上下文 | q8_0 KV 额外内存 | 适合 |
|---|---|---|
| 8192 | ~320 MB | 8 GB 机型 |
| 16384 | ~560 MB | 12 GB 机型 |
| 32768 | ~1040 MB | 不建议在手机上开 |

上下文越大，预填充也越慢。除非确实要处理长文档，否则 8192 够用。

**Q11. 应用被系统杀掉了，模型要重下吗？**

不用。模型文件在私有目录里，不随进程消失。重新打开应用后会自动加载（可能要等几秒）。

**Q12. 下载到一半应用被杀，会接着下吗？**

会。未完成任务记录在 `downloads.json`，下次启动时重新排进队列，带 `Range` 头续传。

前提是服务端支持 `Range`——魔搭大部分文件支持（302 到 CDN 后仍有效）。

**Q13. 提示「空间不足，还差 X」，但我看系统里还有很多空间？**

两点可能：

1. 应用私有目录所在分区（通常是 `/data`）与「内部存储」显示的空间不是一回事；
2. 应用会保留 256 MB 安全水位——下载完还要原子改名、写索引，系统也需要空间做页缓存。

**Q14. 怎么彻底清空？**

卸载应用即可，所有数据（模型、对话、工作区）都在私有目录。

只想清对话：对话页 → 菜单 → 历史会话 → 逐个删除。

只想清模型：本地模型库 → 长按 → 删除。

## 四、智能体

**Q15. 为什么每次都要我确认？烦。**

确认只针对三类会改状态的操作：`shell`、`write_file`、`delete_file`。
弹窗里有「本会话都允许」，点一次这个会话就不再问。

新会话会重置——授权有时效，这是刻意的。

**Q16. 工具卡片显示「拒绝」，但我没点拒绝？**

几种情况：

- 你按了停止，循环在安全点检查到后把该工具标记为未执行；
- 工具名没命中已注册集合（模型输出了格式正确但不存在的工具）；
- 路径越界被 `resolveInside` 挡下。

**Q17. 执行命令报「Permission denied」？**

Android 沙箱限制。应用只能访问自己的私有目录，写不了 `/sdcard`、`/system`。

这是系统级限制，不是 bug。想操作共享目录需要 `MANAGE_EXTERNAL_STORAGE`，应用没有申请（也不该申请）。

**Q18. 联网搜索没结果？**

先是反爬：DuckDuckGo / Bing 对高频请求会返回空页或验证码。等几分钟再试。

再是网络：`fetch_url` 拒绝内网地址，如果你给的是 `192.168.x.x` 会被挡。

**Q19. 抓网页抓回来一堆乱码？**

页面用了非 UTF-8 编码（常见于老的中文站点 GBK）。当前按 UTF-8 解码，非 UTF-8 页面会乱码——这是已知限制。

**Q20. 工作区里的文件怎么拿出来？**

工作区页 → 长按文件 → 分享。会走系统分享面板，可以发到微信 / 邮件 / 保存到网盘。

.html 文件也可以直接在预览页点「浏览器打开」交给系统浏览器。

## 五、构建与调试

**Q21. 首次构建卡在「拉取 llama.cpp」？**

CMake 用 `FetchContent` 从 GitHub 拉 b11205，国内网络可能很慢。两个办法：

```bash
# 1. 预先 clone 一份，指定路径
git clone --depth 1 --branch b11205 https://github.com/ggerganov/llama.cpp /tmp/llama.cpp
./gradlew assembleDebug -PllamaCppDir=/tmp/llama.cpp

# 2. 给 git 配代理
git config --global http.proxy http://127.0.0.1:7890
```

**Q22. 构建报 NDK 版本不匹配？**

项目锁定了 `ndkVersion "27.2.12479018"`。装这个版本，或者改 `app/build.gradle` 里的版本号（需自行验证兼容性）。

**Q23. release 包比 debug 包功能少？**

大概率是 R8 混淆导致。用 `./gradlew assembleDebug` 的包复现，如果 debug 正常就是混淆问题——
检查 `proguard-rules.pro` 是否漏了新的 JNI 符号或反射类。

**Q24. 怎么加一个自己的工具？**

三步：

```java
// 1. 注册名字（ToolCall 校验用）
AgentTools.names().add("my_tool");

// 2. 实现执行
case "my_tool": {
    String arg = c.arg(new String[]{"param"}, "");
    return "结果";                       // 永远返回文本
}

// 3. 加进提示词（否则模型不知道有这个工具）
AgentTools.describe(...)  // 追加一行
```

如果想让它需要确认，在 `AgentTools.risky()` 里加上名字。

**Q25. 单测怎么跑得这么快？**

因为 `core/` 不依赖 Android。`./gradlew testDebugUnitTest` 只编译纯 Java 部分，
99 个用例一秒内跑完（不含 Gradle 启动时间）。

这也是「把规则下沉到 core」的额外好处：测试反馈快，人才愿意写测试。

## 六、隐私与安全

**Q26. 我的对话会被上传吗？**

不会。对话在本地生成、本地存储（`filesDir/chats.json`）。

应用发出的网络请求只有两类：

1. 逛魔搭时的列表 / 详情 / 文件接口（不含你的对话内容）；
2. 你启用联网后，搜索关键词与要抓取的 URL。

**Q27. 模型能读我的短信 / 相册吗？**

不能。应用没有申请这些权限，且 Android 沙箱让进程只能访问自己的私有目录。

`shell` 工具虽然是真 shell，但同样受沙箱限制——`ls /sdcard` 会 Permission denied。

**Q28. 预览页安全吗？**

v2.4.2 起关掉了 `allowUniversalAccessFromFileURLs`，模型生成的 HTML 无法用 `fetch('file:///…')`
读取应用私有文件。相对资源的 `<img>` / `<script>` / `<link>` 仍正常。

注意：预览页仍可访问外网（模型生成的页面可能要加载 CDN 资源）。如果不希望，可以在系统层面断网。

**Q29. 为什么抓取会拒绝内网地址？**

防 SSRF。本地模型完全可能写出 `http://127.0.0.1:8080/admin` 去探测你手机上的服务。

拒绝范围：`localhost`、`127.0.0.1`、`::1`、`0.0.0.0`、`10.*`、`192.168.*`、`172.16-31.*`、
`169.254.*`、`*.local`。

## 七、开发与贡献

**Q30. 代码风格？**

跟现有代码一致即可：

- 4 空格缩进，不用 tab；
- 注释写「为什么」，不写「是什么」——`i++; // i 加一` 是噪音；
- 一个有规则的类配一段 Javadoc，说明它解决什么问题；
- 新的纯逻辑优先放 `core/`，并补单测。

**Q31. 提 PR 前要过什么？**

```bash
./gradlew testDebugUnitTest   # 必须全绿
./gradlew lintDebug           # abortOnError，不能有 error
./gradlew assembleDebug       # 能出包
```

CI 会自动跑前两条。第三条在 CI 里也会跑（`build` job）。

**Q32. 文档和代码不一致怎么办？**

以代码为准，改文档。文档里 [附录 A · API 速查](README.md#附录-a--api-速查) 是从源码抽取的，
其余部分是手写的——手写部分容易过时，发现不对直接提 PR。

**Q33. 为什么不加更多依赖？**

每加一个依赖，APK 变大、构建变慢、出安全问题的面变大。当前只有 5 个直接依赖（AndroidX 必选 + 
Material + Markwon），HTTP、JSON、文件、并发全部用 JDK 自带的。

如果要加，先回答：能不能用 200 行以内自己写完？

## 八、一些设计上的为什么

**Q34. 为什么不用 OkHttp / Retrofit？**

全项目只有 5 个接口，`HttpURLConnection` 够用。引 OkHttp 会让 APK 多 1 MB 以上。

**Q35. 为什么不用 Room 存对话？**

对话是「整体读写」的：加载一个会话、保存一个会话。用一个 JSON 文件 + 原子写更简单，
也没有 schema 迁移的负担。数据量大到需要分页查询时才该上数据库——手机上的会话不会到这个量级。

**Q36. 为什么用 Activity 不用 Compose？**

项目 2024 年起于一份裸 ListView 的实现，逐步演进到 Material 3 + XML。
迁 Compose 是纯收益为「开发体验」的重写，对这个体量不划算。

**Q37. 为什么不支持 iOS / Desktop？**

核心价值在「手机上离线跑」，而 llama.cpp 的 Android 交叉编译、多档指令集、
沙箱文件系统、前台服务都是平台相关的。跨平台会稀释这些细节。

**Q38. 为什么不接入更多模型源（HuggingFace / Ollama）？**

这个项目的定位是「魔搭的一个好用客户端」，不是「通用模型管理器」。

不过 `ModelApi` 的 `Page` 结构是通用的，加数据源只需要实现「列表 / 详情 / 文件列表 / 下载地址」四个方法。
